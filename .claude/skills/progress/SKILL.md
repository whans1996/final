# /progress — 진척 점검

## 절차

1. **수집**
   - `docs/기획서.md`: 기능 목록 표(F-01~F-23, 우선순위, 필수 요구사항 매핑), 4절 마일스톤, 일정 판단 기준
   - `docs/specs/*.md`: 각 파일 헤더의 상태(DRAFT/APPROVED/DONE)와 구현 체크리스트 체크 비율
   - git: `git branch -a`, `git log develop --oneline` (develop에 머지된 feature), 진행 중 feature 브랜치
   - 오늘 날짜로 현재 주차(W1~W5, 버퍼)를 계산한다.
2. **판정**: 기능 상태는 다음 중 하나로 정한다.
   - ⬜ 미착수 (spec 없음) · 📝 spec 작성 · 🔨 구현 중 (APPROVED + 체크 일부) · 🔍 MR 대기 · ✅ 완료 (develop에 머지)
3. **`docs/진행현황.md` 덮어쓰기**

```
# 진행 현황 (YYYY-MM-DD, W? 기준)

## 요약
- P0: 완료 n/19 · 진행 중 n · 미착수 n
- 이번 주 목표(W?) 대비: 정상 / 지연 (지연 기능 나열)
- 판단: (12/07 기준 등 일정 판단 기준에 비춘 결론 한 줄)

## 필수 요구사항 13개
| # | 요구사항 | 기능 | 상태 |

## 기능별
| ID | 기능 | 우선순위 | 오너 | 상태 | 브랜치/spec |

## 이번 주 남은 일 / 리스크
```

4. **보고**: 요약 섹션만 채팅으로 보여 준다. 지연이면 기획서의 일정 판단 기준(예: 12/07에 핵심 흐름 미완성 → P1 포기)을 근거로 무엇을 줄일지 제안한다.
5. 커밋: `docs: 진행현황 갱신 (W?)` — 현재 브랜치가 main/develop이면 커밋하지 않고 사용자에게 알린다.
