## 2. 진행 순서

### 엉킴 방지 규칙
1. **계약 먼저**: BE·FE로 나뉘는 일은 API + `openapi.json` + mock 응답을 먼저 머지하고, 그 날짜를 아래 표에 고정한다.
2. **디자인 기반 먼저**: F-29 공통 PR(토큰·폰트·공통 컴포넌트·앱 셸) 머지 전에는 아무도 화면 스타일을 고치지 않는다. 그 전 FE 작업은 로직만.
3. **공유 파일 한 사람 소유**: F-29 기간 `App.vue`·`main.css`·`components/common`·`HomeView.vue`(랜딩)는 김준섭. 다른 사람이 고치려면 상대 PR 머지 뒤 @멘션.
4. **AI 출력을 바꾸는 PR(프롬프트·선별·매칭)은 기준선 측정 뒤 머지**한다. 학습 루프·화면처럼 출력과 무관한 PR은 언제든 머지.
5. **PR 하나는 1~2일 분량**으로 쪼갠다 (아래 L-1a/b/c처럼).
6. **블라인드 분업**: 김동환은 평가 러너·채점기 코드만(라벨 형식만 보고 dev 데이터로 만든 합성 라벨로 테스트), eval 실행은 김준섭이 하고 점수만 공유한다.
