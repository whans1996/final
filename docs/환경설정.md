# 개발 환경 설정 (Windows 11, PC 4대 공통)

> 다 끝나면 `node scripts/setup.mjs --pc <PC id>`로 PC를 등록하고 점검한다. 모든 항목이 ✅이면 된다.

## 0. 작업 PC 4대

2인이 각자 SSAFY 교육장 PC와 집 PC에서 이어 개발한다. PC마다 네트워크·OS 보안 설정·설치 도구가 달라서, 하네스가 PC를 구분한다.

| PC id | PC |
|---|---|
| `dh-ssafy` | 김동환 SSAFY 교육장 |
| `dh-home` | 김동환 집 |
| `js-ssafy` | 김준섭 SSAFY 교육장 |
| `js-home` | 김준섭 집 |

- **등록**: PC마다 한 번 `node scripts/setup.mjs --pc <id>`. id는 `.harness/pc.json`(커밋 안 됨)에 남고, 전체 점검 결과는 `.harness/env-check.json`에 남는다. 폴더를 다른 PC로 복사하면 hostname이 달라 다시 등록하라고 알린다.
- **사람 구분**: PC id 접두(`dh`·`js`)가 그 PC 사용자의 NOW 파일(`docs/handoff/NOW-dh.md`·`NOW-js.md`)을 정한다 (`node scripts/stamp.mjs --file`). 두 사람이 병렬로 일하므로 각자 자기 NOW 파일만 고친다.
- **세션마다**: SessionStart hook이 PC, 빠른 환경 점검(PC 등록·git hooks·git 사용자·Node·JDK·로컬 설정 파일·FE 의존성·gh 계정·Docker) 중 문제 항목, 그 PC의 주의 사항, 내 NOW 파일 전문과 상대 NOW 요약, develop에 새로 들어온 마이그레이션·openapi 변경을 Claude에게 알린다. **내** NOW `갱신:` 줄과 **내** 작업로그 마지막 항목 중 더 최근 기록의 PC가 지금 PC와 다르면 "직전 작업은 다른 PC" 경고를 띄운다 (상대 기록과 다른 사람 PC에서 쓴 기록은 보지 않는다).
- **인계 기록**: 머리 줄은 `node scripts/stamp.mjs --now`(NOW `갱신:` 줄)·`--log`(작업로그 헤더)로 시계·git·PC 등록에서 만든다. AI 없이 쓰는 `scripts/handoff.mjs`는 작업로그 헤더와 내 NOW `갱신:` 줄을 자동으로 쓴다. 새 세션을 시작하면 `내 NOW 파일보다 나중에 바뀐 미커밋 작업 파일` 경고로 체크포인트 없이 끝난 세션도 알린다.
- **PC별 함정**: 정본은 `scripts/lib/pcs.json`의 `notes`다. 새로 알게 된 함정(예: 교육장 네트워크 차단, 스마트 앱 컨트롤)은 거기에 한 줄 추가하면 다음 세션부터 그 PC에서 주입된다. gh 계정 기대값은 같은 파일의 `github`이다.

## 1. JDK (JAVA_HOME 17 이상 + 컴파일용 21 자동)

백엔드는 Spring Boot 4·Java 21로 컴파일한다(11-18 결정). JDK는 두 가지 역할로 나뉜다.

- **Gradle 실행**: `JAVA_HOME`의 JDK를 쓴다. Gradle 9는 **17 이상**이면 된다. 이미 17로 지정한 PC는 그대로 둔다.
- **컴파일·테스트**: `build.gradle`의 Java 21 toolchain을 쓴다. PC에 JDK 21이 없으면 **첫 빌드 때 Gradle(foojay resolver)이 `~/.gradle/jdks`에 자동으로 받는다**. 따로 설치하지 않아도 된다.

다른 수업에서 Java 8을 써야 할 수 있으므로 **시스템 설정은 그대로 두고 사용자 `JAVA_HOME`만 지정**한다. 같은 이름이면 사용자 변수가 시스템 변수보다 우선한다.

1. JDK 17 이상이 없으면 설치한다. STS도 쓸 거라면 21을 설치해 둘 다 해결한다: `winget install -e --id EclipseAdoptium.Temurin.21.JDK` (또는 adoptium.net)
2. 설치 경로를 확인한다. 예: `C:\Program Files\Eclipse Adoptium\jdk-21.x.x-hotspot`
3. 일반 터미널(관리자 아님)에서:
   ```
   setx JAVA_HOME "<JDK 경로>"
   ```
4. **터미널, IDE, Claude Code를 모두 다시 시작**한다 (이미 떠 있는 프로그램에는 반영되지 않는다).
5. 확인: PowerShell `& "$env:JAVA_HOME\bin\java" -version` → 17 이상
   - 그냥 `java -version`은 PATH 순서 때문에 8이 나올 수 있다. Gradle wrapper와 STS는 `JAVA_HOME`을 쓰므로 빌드에는 문제없다.
6. 첫 빌드(`node scripts/verify.mjs be`)에서 JDK 21 다운로드가 한 번 일어난다 (수백 MB, 몇 분).
7. STS: Window → Preferences → Java → Installed JREs에 **JDK 21** 경로를 추가하고, 프로젝트의 JRE로 지정한다. STS는 자동 다운로드를 하지 않으므로 JDK 21을 설치해야 한다.

**자동 다운로드가 막힐 때** (교육장 네트워크 등): JDK 21을 직접 설치하고 사용자 Gradle 설정 `%USERPROFILE%\.gradle\gradle.properties`에 경로를 적는다. 저장소 파일이 아니므로 커밋되지 않는다.
```
org.gradle.java.installations.paths=C:/Program Files/Eclipse Adoptium/jdk-21.x.x-hotspot
```

## 2. WSL2 + Docker Desktop (Testcontainers용)

백엔드 테스트는 Testcontainers로 실제 MySQL 8을 띄운다. Windows 11 Home은 Docker Desktop을 **WSL2 위에서만** 실행할 수 있다.

1. **관리자 PowerShell**에서:
   ```
   wsl --install --no-distribution
   ```
   WSL과 가상 머신 플랫폼 기능이 켜진다. 끝나면 **재부팅**한다.
   - `wsl` 실행 시 `REGDB_E_CLASSNOTREG` 오류가 나는 상태라면 WSL이 꺼져 있는 것이다. 위 명령으로 해결된다.
2. 재부팅 후 `wsl --status`가 오류 없이 출력되는지 확인한다.
3. Docker Desktop 설치 (관리자 승인 창이 뜬다):
   ```
   winget install -e --id Docker.DockerDesktop
   ```
   설치 옵션에서 **Use WSL 2 instead of Hyper-V**를 선택한다.
4. Docker Desktop을 실행하고 약관에 동의한다. 교육·개인 용도는 무료이며 로그인은 건너뛰어도 된다.
   - 설정에서 "Start Docker Desktop when you sign in"을 켜 두면 테스트 전에 따로 켤 필요가 없다.
5. 확인:
   ```
   docker version
   docker run --rm hello-world
   ```
6. (선택) PC 메모리가 작으면 `%UserProfile%\.wslconfig` 파일을 만들어 WSL 메모리를 제한한다.
   ```
   [wsl2]
   memory=4GB
   ```
   저장 후 `wsl --shutdown`, Docker Desktop 재시작.

## 3. Node.js, MySQL, Git

- Node 24 (24.15 이상. FE의 jsdom 31·vitest 5 요건), MySQL 8 + Workbench, Git
- 최초 1회 저장소 루트에서 `node scripts/setup.mjs --pc <PC id>` (PC 등록, git hook 연결, 환경 점검)
- 로컬 DB (백엔드 `local` 프로필용). MySQL root로 접속해 한 번 실행한다:
  ```sql
  CREATE DATABASE vibenote CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
  CREATE USER 'vibenote'@'localhost' IDENTIFIED BY '<비밀번호>';
  GRANT ALL PRIVILEGES ON vibenote.* TO 'vibenote'@'localhost';
  ```
  저장소 루트에서 `.env.example`을 `.env`로 복사하고 `DB_PASSWORD`를 채운다. 테이블은 백엔드가 시작할 때 Flyway가 만든다.
- 화면 점검(`scripts/ui-check.mjs`)용 브라우저: `cd frontend && npx playwright install chromium` (PC마다 1회)
- 로컬 관리자 계정 (F-00b): 화면에서 평소처럼 가입한 뒤 `.env`에 `ADMIN_BOOTSTRAP_EMAIL=<그 이메일>`을 넣고 BE를 `local` 프로필로 다시 띄우면 기동할 때 그 회원이 ADMIN이 된다. 로그인 중이었으면 새로고침하면 반영된다. 회원이 없거나 탈퇴했으면 WARN 로그만 남긴다. 이메일은 저장소에 커밋하지 않는다

## 4. GitHub

- 개발 저장소: GitHub private (`origin`). `gh` CLI로 로그인한다:
  ```
  gh auth login        # GitHub.com → HTTPS → 브라우저 인증
  gh auth setup-git    # git push가 gh 인증을 쓰도록 연결
  ```
- 계정이 여러 개면 `gh auth status`로 활성 계정을 확인하고 `gh auth switch -u <아이디>`로 바꾼다.
- `git config --global user.name "<이름 또는 아이디>"`, `git config --global user.email "<이메일>"`

## 5. 문제 해결

| 증상 | 원인·해결 |
|---|---|
| `setup.mjs`에서 JDK가 8로 나오고 "다시 시작하세요" 안내 | `setx` 후 재시작하지 않음 → 터미널·Claude Code 재시작 |
| 빌드에서 `Cannot find a Java installation ... languageVersion=21` | JDK 21 자동 다운로드가 막힘 → 1절 "자동 다운로드가 막힐 때" |
| 빌드에서 `Gradle requires JVM 17 or later` | `JAVA_HOME`이 8 등 17 미만 → 1절대로 17 이상으로 지정 |
| 테스트에서 `Could not find a valid Docker environment` | Docker Desktop이 꺼져 있음 → 실행 후 다시 테스트 |
| `npm run lint`에서 "스마트 앱 컨트롤이 oxlint 네이티브를 막아 Docker로 실행합니다" 또는 "oxlint 건너뜀" | Windows 11 스마트 앱 컨트롤(SAC)이 서명 없는 oxlint 바이너리를 막는다(`An Application Control policy has blocked this file`). `frontend/scripts/run-oxlint.mjs`가 Docker(`node:24-alpine`)로 대신 돌리고, Docker도 꺼져 있으면 건너뛴다(PR CI가 검사). 로컬에서도 검사하려면 Docker Desktop을 켜 둔다. SAC를 끌 필요는 없다 |
| `bootRun`이 `app.jwt.secret(JWT_SECRET)은 32바이트 이상` 오류로 멈춤 | `local` 프로필 없이 실행했거나 `.env`에 `JWT_SECRET=`을 빈 값으로 둠 → `--spring.profiles.active=local`로 실행하거나 줄을 주석 처리 |
| Git Bash에서 `gradlew.bat`을 못 찾음 | `./gradlew`(Git Bash) 또는 `.\gradlew.bat`(PowerShell)처럼 경로를 붙인다 |
| `git push`가 403 / Repository not found | 다른 GitHub 계정으로 인증됨 → `gh auth switch`, `gh auth setup-git` |

## 6. 김준섭 착수 체크리스트 (병렬 개발 시작)

11-19부터 영역별 병렬 개발이다 (`docs/기획서.md` 4절). 김준섭 PC(`js-ssafy`·`js-home`)는 아직 이 저장소로 작업한 적이 없으므로 PC마다 처음 한 번 확인한다. `pcs.json`의 `github`는 `JoonseobKim`으로 채워 두었다.

0. `git clone <GitHub 저장소 URL>` 후 `git switch develop`. 로컬 MySQL과 `.env`는 4번에서 만든다
1. `node scripts/setup.mjs --pc js-ssafy`(집은 `js-home`) 결과가 모두 ✅ (특히 `PC 등록`, `git hooks`, `GitHub CLI`, Docker)
2. `gh auth login`으로 `JoonseobKim` 계정 인증(`gh auth status`의 활성 계정), `git config user.name`·`user.email`이 본인 것
3. `node scripts/verify.mjs all` 통과 (BE는 Docker로 Testcontainers, FE는 lint·테스트·빌드). 막히면 5절 표 참고
4. 로컬 MySQL에 `.env.example`대로 `.env`를 만들고 `bootRun`(local 프로필) → Swagger가 열리는지 확인
5. Claude Code에서 `/pickup` 한 번 실행 → `docs/handoff/NOW-js.md`가 "내 작업"으로 주입되고, 김동환 작업이 "상대 작업"(출처 브랜치, 현재 기능, 다음 할 일)으로 보이는지 확인
5-1. Mattermost 알림 채널(7절)에 들어간다. 영역 경계는 `.github/CODEOWNERS`와 `docs/conventions.md` 9절
6. 첫 기능: `/spec F-09` (카드 목록·검색). spec은 바로 써도 되지만, **구현은 A의 공통 기반 PR(concept 도메인·카드 DTO·라우터 분리)이 develop에 머지된 뒤** 그 위에서 한다 (결정로그 11-19). 승인 후 `/implement F-09`. 작업 흐름은 루트 `CLAUDE.md` "작업 흐름"
7. 집 PC를 처음 쓸 때: SSAFY PC에서 `/handoff` → 집에서 `git pull` 후 `/pickup`이 그 상태를 읽는지 확인
8. Codex 리뷰 계정 연결(8절): 안 하면 내 PR에 Codex 자동 리뷰가 달리지 않는다
9. (선택) Notion MCP 연결: 되어 있으면 `/progress`·`/handoff`가 노션 대시보드도 갱신한다 (`docs/notion.md`)

## 7. Mattermost 알림 (사람이 한 번 설정)

`.github/workflows/notify.yml`이 PR 열림·머지와 사람별 NOW push를 Mattermost 채널로 보낸다. 웹훅 URL은 비밀이라 저장소 secret으로만 넣는다 (하네스는 `gh secret`을 막으므로 사람이 한다).

1. SSAFY Mattermost에서 두 사람만 있는 채널(예: `vibenote-dev`)을 만들고 김준섭을 초대한다
2. **두 사람이 각자** 메뉴 → 통합(Integrations) → Incoming Webhook 추가 → 같은 채널 선택 → 생성된 URL 복사.
   수신 웹훅 글은 **웹훅을 만든 사람 이름**으로 올라가고 SSAFY 서버는 이름 바꾸기를 무시한다. 한 사람 웹훅만 쓰면 상대 활동도 그 사람 이름으로 보인다 (11-19)
3. GitHub 저장소 → Settings → Secrets and variables → Actions → New repository secret: 김동환 웹훅은 `MATTERMOST_WEBHOOK_URL_DH`, 김준섭 웹훅은 `MATTERMOST_WEBHOOK_URL_JS`.
   워크플로는 이벤트를 일으킨 사람(PR 열기·머지·push)의 웹훅으로 보낸다. 그 사람 것이 없으면 공용 `MATTERMOST_WEBHOOK_URL`(예전 방식), 그것도 없으면 등록된 아무 웹훅으로 보낸다
4. 다음 PR을 열거나 feature 브랜치에 NOW 파일을 push하면 채널에 내 이름으로 메시지가 오는지 확인한다 (Actions 로그 "보낸 사람: dh|js"). secret이 하나도 없으면 워크플로는 "건너뜁니다"만 남기고 성공한다
5. 로컬 확인: `GITHUB_EVENT_NAME=push GITHUB_EVENT_PATH=<이벤트 JSON> node scripts/notify-message.mjs`

## 8. Codex 리뷰 계정 연결 (사람마다 한 번)

Codex 봇은 **요청한 GitHub 계정이 Codex(ChatGPT)에 연결돼 있어야** 리뷰한다. PR을 열 때 도는 자동 리뷰는 PR 작성자 계정, `@codex review` 재요청은 댓글 단 계정 기준이다. 연결이 안 된 계정의 PR에는 자동 리뷰가 아예 달리지 않고, 재요청에는 "create a Codex account and connect to github" 안내만 달린다 (11-19 PR #28·#30에서 확인).

1. 봇 안내 링크(https://chatgpt.com/codex/cloud/settings/connectors)에서 본인 ChatGPT 계정으로 GitHub(본인 아이디)를 연결하고, 이 저장소 접근을 허용한다
2. Codex 설정 → Code review에서 이 저장소의 Code review와 **Automatic reviews**를 켠다
3. 확인: 열린 내 PR에 `node scripts/codex-review.mjs <PR> --request --wait --status`. `COMPLETE`나 `FINDINGS`가 나오면 끝. `ERROR Codex 계정 미연결 (@아이디 …)`이면 1·2를 다시 확인한다

리뷰 상태는 PR 체크 `Codex`(⏳/❌/✅)로도 보인다 (`.github/workflows/codex-status.yml` + `--status`). 머지를 막지는 않는다(private 무료 플랜은 브랜치 보호 불가).
