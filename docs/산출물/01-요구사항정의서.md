# 요구사항 정의서 — 바이브노트 (VibeNote)

> 작성 상태: ✅ 초판 (2026-11-17) · 원본: `docs/기획서.md` 2절. 기능이 바뀌면 기획서와 이 문서를 함께 고친다.

## 1. 개요

| 항목 | 내용 |
|---|---|
| 서비스 | AI로 코딩하는 주니어와 개발자 지망생을 위해, AI가 쓴 코드를 수준에 맞는 구조 설명과 개념 카드로 풀어 주고 퀴즈와 복습으로 지식을 정착시키는 코드 이해 학습 플랫폼 |
| 사용자 | 비회원, 회원(학습 수준: 입문·주니어·숙련), 관리자 |
| 범위 | 지원 스택 Java·Spring·MyBatis·JavaScript·Vue, 공개 GitHub/GitLab 저장소 URL 또는 ZIP(200파일·10MB 이하) |

### 구분 기준

| 구분 | 의미 | 명세서 대응 |
|---|---|---|
| 기본 | 서비스 핵심 흐름과 회원 관리. 반드시 구현 | 명세서 "기본 기능(필수)" |
| 추가 | 소셜, 챌린지, 커뮤니티 | 명세서 "추가 기능" |
| 심화 | 생성형 AI 활용 기능 | 명세서 "심화 기능" |
| 확장 | 일정 여유가 있을 때 구현 | - |

우선순위: **P0** 반드시 구현 · **P1** P0 완성 후 · **P2** 여유가 있을 때

## 2. 기능적 요구사항

| 번호 | 분류 | 요구사항명 | 요구사항 상세 | 구분 | 우선순위 | 관통 필수 |
|---|---|---|---|---|---|---|
| F-01 | 회원 | 회원가입 | 이메일·비밀번호·닉네임을 입력하고 학습 수준(입문/주니어/숙련)을 선택해 가입한다 | 기본 | P0 | ② |
| F-02 | 회원 | 로그인·로그아웃 | 이메일·비밀번호로 로그인하면 JWT(Access + Refresh)를 발급하고, 만료 시 재발급한다. 로그아웃하면 Refresh 토큰을 폐기한다 | 기본 | P0 | ① |
| F-03 | 회원 | 프로필 관리·회원 탈퇴 | 내 정보 조회·수정(닉네임, 소개, 수준), 학습 통계(분석 수, 학습한 카드, 퀴즈 정답률) 조회. 탈퇴는 비활성화 방식으로 처리하고 개인정보를 마스킹한다 | 기본 | P0 | ⑤ |
| F-04 | 소셜 | 팔로우·활동 피드 | 다른 회원을 팔로우·언팔로우하고 팔로워·팔로잉 목록을 조회한다. 팔로우한 사람의 공개 활동(분석, 리뷰, 찜, 게시글, 챌린지)을 피드로 본다 | 추가 | P0 | ⑥ |
| F-05 | 분석 | 분석 요청 | 공개 저장소 URL 또는 ZIP을 등록한다. 지원 스택과 크기를 검증하고 `.env`·키 패턴을 제거한 뒤 비동기로 분석한다. 분석마다 설명 수준을 바꿀 수 있다. 내 분석 목록과 진행 상태를 조회한다 (F-05a ZIP, F-05b URL) | 기본 | P0 | ⑬ |
| F-06 | 분석 | 개요·파일별 설명 | 프로젝트 목적, 레이어 구조, 주요 파일의 역할을 수준에 맞춰 설명한다. 분석 상세(개요·파일)를 조회한다 | 기본·심화 | P0 | ⑬ |
| F-07 | 분석 | 실행 흐름 설명 | 탐지된 API 중 사용자가 고른 1~3개의 요청→응답 흐름을 단계별로 설명한다(결과 캐시) | 심화 | P0 | ⑬ |
| F-08 | 개념 카드 | 개념 추출·연결 | 코드에 쓰인 개념을 추출해 기존 카드와 연결하고, 없는 개념은 AI 초안 카드를 만들어 검수 대기로 둔다 | 심화 | P0 | ⑦ ⑬ |
| F-09 | 개념 카드 | 목록·검색 | 키워드·카테고리·난이도로 필터하고 인기순·최신순으로 정렬한다 | 기본 | P0 | ⑧ |
| F-10 | 개념 카드 | 상세 조회 | 쉬운 설명, 예제 코드, 내 코드에서 등장한 위치, 관련 카드를 보여 준다 | 기본 | P0 | ⑨ |
| F-11 | 개념 카드 | 리뷰 | 별점(1~5)과 한 줄 리뷰(1~200자)를 작성·조회하고, 내 리뷰를 수정·삭제한다 (카드당 1인 1리뷰) | 기본 | P0 | ⑩ |
| F-12 | 개념 카드 | 찜 | 카드 상세에서 찜하기·해제(내일 복습 계획 자동 추가), 프로필에서 회원의 찜 목록을 조회한다 | 기본 | P0 | ⑪ |
| F-13 | 관리자 | 개념 카드 관리 | 시드 카드 등록, AI 초안 카드 검수(수정·공개·삭제) | 기본 | P0 | ⑦ |
| F-14 | 학습 | 코드 이해 퀴즈 | 분석한 코드로 객관식 5~10문항을 생성하고 채점·해설을 제공한다. 점수로 이해도를 표현하고 오답 개념을 기록한다 | 심화 | P0 | ⑫ ⑬ |
| F-15 | 학습 | 복습 계획 | 오답·찜 카드를 날짜별 복습 목록에 담고 완료를 체크한다 | 추가 | P0 | ⑫ |

| F-17 | 커뮤니티 | 게시판 | Q&A·학습 후기·자유 게시판. 게시글 작성·조회·수정·삭제·검색, 분석 결과나 개념 카드 첨부 | 추가 | P0 | ③ |
| F-18 | 커뮤니티 | 댓글 | 댓글 작성·조회·수정·삭제(수정·삭제는 본인만) | 추가 | P0 | ④ |
| F-19 | 분석 | 분석 관리 | 분석 제목·메모 수정, 공개/비공개 설정(완료된 분석만 공개), 삭제(끝난 분석만, 퀴즈 풀이 기록은 유지), 공개 분석 열람(다른 회원 읽기 전용) | 기본 | P0 | ③ ⑥ ⑦ |

## 3. 비기능적 요구사항

| 번호 | 분류 | 요구사항명 | 요구사항 상세 | 검증 방법 |
|---|---|---|---|---|
| NF-01 | UX | 사용 편의성 | 사전 지식이 없는 사용자도 가입 후 안내 없이 분석 요청까지 할 수 있다. 랜딩에서 샘플 분석 결과를 미리 보여 준다 | 시연 시나리오 점검 |
| NF-02 | UI | 반응형 | 375px(모바일)~1440px(데스크톱) 폭에서 가로 스크롤 없이 모든 화면을 사용할 수 있다 | 화면 자동 점검(데스크톱·모바일) |
| NF-03 | 효율성 | 응답성 | 목록·검색 API는 시드 데이터 기준 500ms 이내에 응답한다. 분석 요청은 1초 이내에 접수(202)하고 처리는 비동기로 한다 | 통합 테스트 응답 시간 측정 |
| NF-04 | 효율성 | 정확성 | 공개 개념 카드는 관리자 검수를 거친 것만 노출한다. LLM 출력은 JSON 스키마로 검증하고 실패 시 1회 재시도한다. 지원 스택 외 코드는 분석하지 않는다 | 테스트, 프롬프트 평가 |
| NF-05 | 보안 | 보안 | 비밀번호 BCrypt 해시, JWT 인증·인가, 업로드 파일 형식·크기 제한, Zip Slip·SSRF 방어, 업로드 코드의 비밀 정보 제거 | 보안 점검 리뷰, 테스트 |
| NF-06 | 신뢰성 | 가용성 | LLM 장애나 한도 초과 시 로컬 Ollama로 자동 전환하고, 생성 결과는 캐시해 재사용한다 | 장애 상황 Mock 테스트 |
| NF-07 | 운영 | 비용 관리 | 사용자별 일일 분석 횟수를 제한하고 모든 LLM 호출의 토큰 사용량을 기록한다 | 사용량 로그 집계 |
