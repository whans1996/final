# 로드맵 (일정 정본)

> 기간 × 사람 × 트랙 할 일, 넘겨주는 시점, 공통 일정의 **정본**이다 (R-1, `docs/기획서.md` 7.7절). 근거는 `docs/점검/2026-11-26-2차점검.md` 2절과 기획서 7절에 남기고, **일정은 이 파일에서만 고친다**.
> 하네스(`scripts/lib/roadmap.mjs`)가 아래 표를 읽어 세션 시작 배너, `/pickup` 로드맵 블록, `/handoff` "다음 항목"에 보여 준다. 표 머리와 열 순서를 바꾸지 않는다 (`node --test scripts/test/roadmap.test.mjs`가 이 파일을 파싱한다).
> **상태(⬜ → 🔨 → ✅)는 여기 쓰지 않는다.** 머지된 PR 본문의 `Roadmap: <ID>` 줄이면 ✅, `Roadmap: <ID> (일부)`·열린 PR·이름에 ID가 든 원격 브랜치(`feature/<ID>-slug`)면 🔨로 계산한다. 끝 날짜가 지났는데 ✅가 아니면 ⚠️다. 확인: `node scripts/roadmap.mjs`. 로드맵 전에 머지한 PR이나 줄을 빠뜨린 PR은 그 PR 본문에 `Roadmap: <ID>` 줄을 추가한다(`gh pr edit <번호> --body-file`, 예: #192 HP-1·#175 D-1). 빠뜨리면 그 항목이 ⬜로 남아 ⚠️와 의존 대기(⏳)가 퍼진다.

- 관리: **일정·하네스 관리는 김동환(A)이 주도한다** (11-26 결정). 김준섭(B)은 바꿀 일정을 A에게 알리거나 이 표를 고치는 PR을 올리고, A가 확인해 머지한다. 이 표와 다른 NOW·문서의 날짜는 이 표를 따른다.
- **바로 반영 (11-27)**: 항목이 일찍 끝나거나 늦어지면 그 즉시 시작·끝을 실제 날짜로 고치고, 비게 된 기간으로 뒤 항목을 당기거나(의존이 풀린 항목부터) 늦어진 만큼 민다. 넘겨주는 시점도 같이 고친다. 끝난 항목의 끝 날짜는 머지일(KST)이다.
- 연도: 2026
- 담당: A = 김동환, B = 김준섭, A·B = 둘 다. 날짜는 `MM/DD`, 기간은 시작~끝(끝 날짜 포함).
- 의존: 먼저 ✅가 되어야 시작할 수 있는 항목 ID (쉼표로 구분, 없으면 `-`).
- 모델: 그 항목 세션의 메인 모델/effort (CLAUDE.md "세션 운영").
